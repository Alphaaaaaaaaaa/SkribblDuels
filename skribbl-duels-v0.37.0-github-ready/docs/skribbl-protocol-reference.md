# Introduction
This is the write-up of the networking protocol used by [Skribbl.io]( Skribbl.io is an online multiplayer drawing game where a player draws a word, and the other players attempt to guess what the first player is attempting to draw. The site's backend consists of [Express.js]( to serve HTTP requests, and [socket.io]( to handle messages sent over a [websocket connection]( Skribbl.io utilizes socket.io to send and recieve in-game messages (or packets) as JSON messages to and from clients. These packets are dynamic, meaning they have no fixed layout.

This documentation is divided into three parts: the [login procedure]( [the websocket protocol itself]( and [a list of words used by Skribbl.io for English lobbies]( The login procedure section will explain how Skribbl.io gets a server URL to establish a websocket connection with. The protocol section details a list of all packets that a Skribbl.io client can send or recieve along with the purpose of the packet, a description of the packet's structure, and example packets that have been sent in-game. Along with this, several DataTypes are listed which are used by the protocol. These datatypes can consist of enums to correlate ID numbers to a human-readable format, structure of arrays, objects and their members, and BitField values. The last part, a list of all words, is for reference and is automatically generated by [skribbl.io-word-dumper](

The contents of this documentation is used by my project, [Skribbler]( to be able to create headless clients that can join Skribbl.io lobbies.

# Login
Skribbl.io initializes a connection to their servers by first getting a server URI to connect with. The client starts a connection to the server URI with socket.io and sends a [login packet]( to tell the server information about the client. Upon successful login, the server assigns a lobby to the client and sends information about the lobby through the [Lobby Data]( packet.

## POST `
This is the first request sent by the client once it presses the 'Play' button. If the player attempts to join a random public lobby or create a private lobby, the client sends the current language to the server. If instead the player is trying to join a custom lobby (through `skribbl.io/?XXXXXXXX` urls), the client instead sends the lobby ID to the server. The server then responds with a server URI which the client should establish a socket.io connection with.

```
User-Agent: <user agent>
```

Request Body:
```
lang=<language ID>
```

## GET `wss://<server uri>/<port>/?EIO=4&transport=websocket`
Once the client recieves the server URI from the `/play` request, a socket.io connection is established. The port number should not be included in the request's hostname, but rather in the path. If incase a websocket connection cannot be established, such as in the case of the browser not supporting websockets, then socket.io will use using [polling]( instead of a websocket connection to send and recieve data from the server.

Request Headers:
```
Accept: */*
Accept-Encoding: gzip, deflate, br, zstd
Accept-Language: en-US,en;q=0.5
Cache-Control: no-cache
Connection: keep-alive, Upgrade
Origin:
Pragma: no-cache
Sec-Fetch-Dest: empty
Sec-Fetch-Mode: websocket
Sec-Fetch-Site: same-site
Sec-GPC: 1
Sec-WebSocket-Extensions: permessage-deflate
Sec-WebSocket-Key:
Sec-WebSocket-Version: 13
Upgrade: websocket
User-Agent: <user agent>
```

Once the client starts the websocket connection, it sends the following message:
```
40
```

## First Socket.io Message
Once the websocket connection is established, the socket.io server [sends information about the connection which is used by the socket.io-client]( This includes information about the session ID, which is used for polling; upgrades that the server supports; and ping timeout and intervals which is used to confirm that the socket.io connection is still alive. This connection message has the following structure:

| Field | Type | Description |
| ------------ | ------ | ------------------------------------ |
| sid | String | Session ID used for polling |
| upgrades | Array | Upgrades that are available |
| pingInterval | Number | The time which ping packets are sent |
| pingTimeout | Number | How long to wait for a ping response |
| maxPayload | Number | Max size of a websocket mesage |

## Client Response
Once the socket.io connection handshake is established, the client is ready to send packets. The first packet sent is the Login packet, which is responsible for telling the server if it should join a random lobby, join a pre-existing lobby, create a private lobby, and other information such as the player name, avatar, and language.

Example Packets:
- `["login",{"join":"","create":0,"name":"Timothy","lang":"0","avatar":[4,16,11,-1]}]` (Joining a random public lobby)
- `["login",{"join":"VqHcNen0","create":0,"name":"Timothy","lang":"0","avatar":[4,16,11,-1]}]` (Joining an existing lobby)
- `["login",{"join":0,"create":1,"name":"Timothy","lang":"0","avatar":[4,16,11,-1]}]`(Creating a private lobby)

### Packet Structure (C->S)
| Field | Type | Description |
| ------ | ---------------- | ------------------------------------ |
| join | String \| Number | Lobby code to join, normally blank |
| create | Number | If a private lobby should be created |
| name | String | Name of the player that is joining |
| lang | [Language]( | Language of the player that is joining |
| avatar | [UserAvatar]( | Avatar of the player that is jonning |

## Server Response
Once the server recieves the login packet, it assigns a lobby to the player. It then sends the [Lobby Data](h[ttps://gist.github.com/MrDiamond64/b2081f2cb4ca6d11e848edaeb5ae1814#language]( packet to the player to finalize the login procedure. This is the end of the procedure and now the client is able to interact with the game.

## Join Error
If the server does not allow the client to join the lobby, a `joinerr` packet is sent to the client and the websocket connection is closed.

Example Packets:
- `["joinerr",100]`

The number in the packet refers to the [JoinError]( datatype.

# Data Packets
Data Packets are websocket messages that describe in-game actions, such as drawing, sending a text message, or liking/disliking a drawing.

Example Packets:
- `42["data",{"id":2,"data":0}]`

The packet ID is in the first example identifies the packet as the [Player Remove]( packet, this is always a positive integer value. The data value is information about the Player Leave packet, in this case it describes the user ID of the player who left. The type of the data value can vary; in the first example it is a Number, though it could be an object for other data packets.

## [1] Player Add
When a new player joins the lobby, the server sends this packet to all online players.

Example Packets:
- `["data",{"id":1,"data":{"id":1,"name":"","avatar":[8,0,0,-1],"score":0,"guessed":false,"flags":0}}]`

### Packet Structure (S->C)
| Field | Type | Description |
| ----- | --------------------------------------------------------------------------------------- | ---------------- |
| data | [User]( | User that joined |

## [2] Player Remove
When a player leaves the lobby, the server sends this packet to all online players.

Example Packets:
- `["data",{"id":2,"data":{"id":1,"reason":0}}]`

| ----------- | ------ | ----------------- |

| data.id | Number | User ID that left |
| data.reason | [LeaveReason]( | Leave Reason |

## [18] Select Word
Packet ID 18 is sent by the client to the server when it selects the word to draw.

If the lobby has the [WordMode]( setting set to either Normal or Hidden, the data field in this packet can just be the word's index sent [in state ID 3]( For example, if the available words list was `["cat","dog","bush"]`, to select the word "cat" the data field would be set to `0`, to select the word "dog" the data field would be set to `1`, and so on.

If instead the WordMode setting is set to Combination, the data field in this packet will be an array of indicies. The available words list sent in state ID 3 will remain as a single dimensional array. To determine which part of the available words list is part of stage one or two of the word selection screen, you can split the array in half. For example, if the available words list was `["mouse","trophy","block","piano","rainbow","chair"]`, splitting the array in half would result in the following arrays: `["mouse","trophy","block"]` and `["piano","rainbow","chair"]`. The data field in this packet will be a list of indicies for both of split arrays. Using the example above, if you were to select the words "mouse" and "chair", the data field in this packet would be `[0,2]`, as index of the word "mouse" in its array is zero, and the index of the word "chair" in its array is two.

Example Packet:
- `["data",{"id":18,"data":2}]` (Selecting a word when WordMode is not set to Combination)
- `["data",{"id":18,"data":[2,2]}]` (Selecting a word when WordMode is set to Combination)

### Packet Structure
| Field | Type | Description |
| ----- | ------------------- | -------------------------------------- |
| data | Number\| Number\[\] | Index of the word sent in packet id 11 |
